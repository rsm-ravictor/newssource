# SETUP — handing this project to another machine

Everything a new person needs to get this repo running locally, in the order they need it.
Read this file first; it points at the other docs rather than repeating them.

- `README.md` — what the tool does, screen by screen. Read after step 4.
- `CONTEXT.md` — the original brief and the privacy constraint. Read if you are changing behavior.
- `TRITONAI_SETUP.md` — the vendored TritonAI client doc. Reference only; **its model table is
  stale** (see "Known gotchas").

---

## 0. What this is, in 30 seconds

A local pipeline that watches a roster of commercial **tenants** and **competitors** for
meaningful news, judges each article against written criteria with an LLM, and renders a
client-ready HTML email digest.

```
rosters (.md)  ->  Tavily news search  ->  LLM judging  ->  digest.html  ->  preview / snapshot
  watchlist.py         search.py            judge.py        render.py      build_preview.py

              all driven by serve.py (local web runner); history in data/history.db (db.py)
```

Two things are worth knowing before you touch anything:

1. **The runner is local-only by design.** `serve.py` binds to `127.0.0.1`. It has no auth and it
   holds live API keys, so it must not be exposed. See "Running it on a server" below.
2. **Privacy is a hard constraint, not a preference.** Only an entity's **name and city** ever
   leave the machine. Rents, addresses, lease terms and the roster itself stay local. Tests
   enforce this. Do not route around them.

## 1. What transfers over git, and what does not

`git clone` gets you the code, the config, the templates, and **fictional** sample data — enough
to run the offline preview immediately.

It does **not** get you these, because `.gitignore` deliberately excludes them:

| Not in the repo | What it is | How to get it |
|---|---|---|
| `.env` | API keys | Create your own from `.env.example` (step 3) — **never** copy someone else's |
| `tenant-list.md`, `competitor-list.md` | the real rosters | Handed over out of band, or write your own (step 4) |
| `data/watchlists/*.txt`, `*.md` | generated rosters | Regenerated by `ingest.py`, or handed over |
| `data/notes/` | reviewer notes that feed the judging prompt | Hand over if you want continuity |
| `data/history.db` | run history / de-dupe memory | **Leave it behind.** A fresh machine should start with an empty history |
| `.venv/` | virtualenv | Rebuild locally (step 2) — it is not portable |

**Move the private files over something encrypted** — a shared drive, a password manager, an
internal file share — not email or chat. Keys should be issued per person, not shared: TritonAI
keys are tied to a UCSD login and Tavily credits are billed per account.

## 2. Prerequisites and install

- **Python 3.11+** (developed on 3.13; the code uses `X | Y` type syntax, so 3.10 is the floor).
- **git**.
- For live runs only: a TritonAI key and a Tavily key (step 3). TritonAI may require the campus
  network or VPN.

```bash
git clone git@github.com:rsm-ravictor/newssource.git
cd newssource

python -m venv .venv
.venv\Scripts\activate            # Windows (PowerShell / Git Bash)
source .venv/bin/activate         # macOS / Linux

pip install -r requirements.txt
```

Six dependencies, all pure-Python: `openai`, `python-dotenv`, `pydantic`, `jinja2`, `pyyaml`,
`tavily-python`. No database server and no build step — SQLite is in the standard library.

**Checkpoint — this must work with no keys and no network:**

```bash
python -m unittest discover -s tests     # 148 tests, all offline
python build_preview.py --open           # builds and opens the preview from committed fixtures
```

If those two pass, the install is good and everything after this is configuration.

## 3. Keys

```bash

```

Then fill it in. `.env` is gitignored; keep it that way.

| Variable | Needed for | Where |
|---|---|---|
| `TRITONAI_API_KEY` | all judging | <https://tritonai-api.ucsd.edu/> — sign in with your UCSD login |
| `TAVILY_API_KEY` | live runs only | <https://app.tavily.com/> — the free tier is enough to start |


A `403 team_model_access_denied` here is about the model id, not the key — see gotchas.

## 4. Your rosters

The two files at the repo root are the point of reference for a live run, and they are the files
you have to supply. `config/report_types.yaml` names them (the `watchlist:` key under each report
type), so you can point at different filenames instead of matching these.

`tenant-list.md` — one table per segment; the `#` column is the **priority rank**, and it changes
both judging and reading order:

```markdown
## Office

| # | Tenant Name | City |
|---|-------------|------|
| 1 | Example Holdings | San Diego |
```

`competitor-list.md` — one table per market, with the city inherited from the `## City` heading:

```markdown
## San Diego

| Company | Category | Ticker | Notes |
|---------|----------|--------|-------|
| Example Realty | REIT | EXR | |
```

`watchlist.py` reads these **by column name**, so column order does not matter and prose between
tables is ignored — the rosters stay readable documents. `data/watchlists/*.example.txt` shows the
minimal flat-file form if you would rather start there. If you have the AAT Excel workbooks,
`python ingest.py --list` describes them and a plain `python ingest.py` converts them.

Then read the `criteria` and `evidence_standard` blocks in `config/report_types.yaml` — that text
*is* the system prompt the model receives. Adjust it to what your side cares about before spending
credits.

The two `*-intelligence-rubric.md` files at the repo root are a generated, human-readable copy of
those blocks; nothing reads them at runtime. After changing the YAML, run
`python export_rubrics.py` to refresh them (`--check` fails if they are stale), and commit both.

## 5. First live run

Work up in this order; each step costs more than the last.

```bash
python generate_summaries.py --verbose --limit 2   # LLM only, against committed fixtures
python db.py                                       # creates data/history.db, prints its state
python serve.py                                    # http://127.0.0.1:8765
```

In the runner: pick a lookback (1 / 7 / 30 / 90 days), **set "Cap entities" to something small
like 5**, and press **Push run now**. Nothing runs on page load or on a schedule — a run only ever
happens because someone pressed that button.

**Cost: 2 Tavily credits plus 1 LLM call per entity.** A full 626-name tenant roster is roughly
1,250 credits, so keep the cap on while you are finding your feet. The runner shows the estimate
before you click.

An empty digest is a correct result, not a broken one. The criteria are built to reject most
articles — in testing, 10 of 10 Illumina articles were correctly excluded.

Use `python serve.py --port 9000 --no-browser` if 8765 is taken or the box is headless.

## 6. Running it on a server

`serve.py` has **no authentication** and reads live API keys from `.env`. Anyone who can reach the
port can spend your Tavily credits and read real tenant news.

So leave it bound to loopback and reach it through an SSH tunnel:

```bash
# on the server
python serve.py --host 127.0.0.1 --port 8765 --no-browser

# from your laptop
ssh -L 8765:127.0.0.1:8765 you@server        # then open http://127.0.0.1:8765
```

`--host 0.0.0.0` exists, but treat it as a mistake unless the box is behind a VPN *and* an
authenticating reverse proxy. The published GitHub Pages copy (`docs/`) is the static preview and
has no Run button — that separation is the point.

`docs/` is **public**. `build_preview.py` writes fictional sample data there. Only **Save as
snapshot** overwrites it with real findings — do not commit the result of that.

## 7. Known gotchas

- **The model table in `TRITONAI_SETUP.md` is out of date.** Of the seven ids it lists, only
  `api-gpt-oss-120b` still resolves; the rest return `403 team_model_access_denied`. The project
  default is `claude-sonnet-4-6`, set at `utils/connect.py:46` — that `DEFAULT_MODEL` line is the
  only edit `connect.py` is meant to receive. `python smoke_test.py` re-lists what is actually live.
- **`utils/connect.py` is verbatim-locked.** Every call routes through it; there is no second
  client anywhere. Fixes belong at the call site.
- **Structured output is not enforced by the proxy.** TritonAI accepts
  `response_format={"type": "json_object"}` but does not guarantee it, so `generate_summaries.py`
  retries once and repairs fenced or unwrapped JSON. That is a parsing repair, not a model
  fallback — do not simplify it away.
- **TritonAI may require the campus network or VPN.**
- **`data/history.db` is machine-local.** It is what stops a story being judged or alerted twice.
  Copying it between machines mostly copies confusion; start fresh.
- **The roster tests skip themselves** when the gitignored rosters are absent, so a green test run
  on a fresh clone does not mean your rosters parse. Re-run the tests once you have added them.
- **Windows**: use `.venv\Scripts\activate`, and close the `.docx` files before any git operation —
  Word leaves `~$` lock files behind.
